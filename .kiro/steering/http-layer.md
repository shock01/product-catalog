# HTTP Layer Architecture

## Principle
The HTTP layer is **infrastructure**. It translates HTTP into domain operations and back — nothing more. Business logic lives in `internal/domain`. Application orchestration (fetch, validate, save, dispatch) lives in `internal/usecase`. See `.kiro/steering/domain-vs-application-services.md`.

## Layer Map

```
internal/
├── gen/            # Generated by oapi-codegen — never edited by hand
│   └── api.gen.go  # StrictServerInterface, request/response types
├── usecase/        # Application use-cases (replaces internal/app)
│   ├── product_commands.go
│   └── product_queries.go
└── handler/        # HTTP infrastructure — implements gen.StrictServerInterface
    └── product.go
```

## Code Generation
- Tool: `oapi-codegen` (strict server mode with chi)
- Config: `api/oapi-codegen.yaml`
- Output: `internal/gen/api.gen.go`
- Regenerate: `make generate`
- **Never edit files under `internal/gen/`**

The correct change order is always:
1. Edit `api/openapi.yaml`
2. `make generate`
3. Implement/update the handler

## Handler Rules (`internal/handler`)
- Implements `gen.StrictServerInterface` — one method per OpenAPI `operationId`
- Receives a use-case interface, not a concrete type
- Maps HTTP request → use-case input, use-case output → HTTP response
- Returns `gen.*Response` structs; never writes directly to `http.ResponseWriter`
- No business logic, no SQL, no cache calls
- Error mapping lives here: `domain.ErrNotFound` → `404`, `domain.ErrVersionConflict` → `412`, etc.

```go
type ProductHandler struct {
    commands ProductCommands
    queries  ProductQueries
}

func (h *ProductHandler) GetProduct(ctx context.Context, req gen.GetProductRequestObject) (gen.GetProductResponseObject, error) {
    p, etag, err := h.queries.GetByID(ctx, req.Id)
    if errors.Is(err, domain.ErrNotFound) {
        return gen.GetProduct404JSONResponse{...}, nil
    }
    // ...
}
```

## Use-Case Rules (`internal/usecase`)
- Pure Go — no HTTP types, no `net/http` imports
- Commands return only `error`; queries return a value and `error` (CQRS — see `cqrs.md`)
- Owns transaction boundaries and outbox dispatch
- Depends on `domain` interfaces, not concrete repository types

```go
// Queries
type ProductQueries interface {
    GetByID(ctx context.Context, id uuid.UUID) (*domain.Product, string, error)
}

// Commands
type ProductCommands interface {
    Create(ctx context.Context, p *domain.Product) error
    Update(ctx context.Context, p *domain.Product) error
    Patch(ctx context.Context, p *domain.Product) error
    Delete(ctx context.Context, id uuid.UUID, version int) error
}
```

## Wiring (`cmd/api/main.go`)
- Construct repositories → construct use-cases → construct handler → register with chi router via `gen.HandlerFromMux`
- No business logic in `main.go` — only dependency wiring and server startup

## What Does NOT Belong in a Handler
- Validation beyond what oapi-codegen strict mode already enforces
- Domain invariant checks (those live in `domain.Product.Validate()`)
- Direct database or cache calls
- Constructing domain events
